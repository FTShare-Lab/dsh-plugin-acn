# 已知兼容限制

## 网页配置与会话

网页模型选择针对 ACN 后台任务；前台聊天模型仍由 DSH 选择。团队凭据仍通过宿主环境变量提供，页面只保存变量名。保存成功代表配置落盘并激活，网络可用性通过 `/acn-status` 与实际工具调用确认。

网页切换身份或知识目录后必须新建会话，旧会话及无法验证父会话来源的历史 fork 被阻止；原知识和会话记录不会删除或迁移。只改模型或连接参数时保留存活会话的冻结快照。配置页需要 DSH `0.2.1-rc.2` 的 ConfigEditor、Gateway、模型及插件管理客户端服务，终端最小组合不显示网页表单。实测范围见[网页配置验收](validation/2026-10-24-web-configuration.md)。

会话身份现已写入宿主持久日志，离线修改 YAML 后重启也不能改绑旧会话。升级前没有身份记录的历史会话需新建；未配置 Agent ID 时不限制宿主对话。个人模式中修改过的待传团队版本会暂停，回到团队后需核对修订或执行受审查的整合重绑，不会自动发布这些变化。

## UTC 规范时间超出四位年份

ACN `0.3.3` 的时间格式化与反序列化在极端年份存在不对称：合法 offset 时间可换算到 `+10000` 或 `-0001`，格式化能输出，参考实现的 RFC 3339 反序列化器却拒绝读回。

M1 选择拒绝 UTC 规范年份小于 0 或大于 9999 的输入，避免写出不可回读的知识文件。32 组兼容基准均位于可往返范围；导出器另外核对两个源端反例，TypeScript 有对应拒绝测试。常规时间、纳秒、长小数截断和闰秒已验证。

以后升级参考实现时应重新检查此边界，再决定是否放宽。这个限制不需要修改 ACN 仓库，也不影响 M2 的 Claim 工具接入。

M4 已在本地 Node 22/24 启动真实 ACN 0.3.3 完成契约验证。远端 CI 尚未运行；启用时需设置仓库变量 `ACN_REFERENCE_REPOSITORY`，私有跨仓库访问另设 `ACN_REFERENCE_TOKEN` secret。未把真实账户或连接信息写进仓库；缺少变量时必跑的契约 job 会明确失败，不会静默跳过。

## 整理质量与后续范围

2026-10-26 的真实业务争议暴露出自动仲裁阻断：29 份团队 Claim 摘要保持不变，Router 模型重排后的 top-k 候选集合仍会在相同查询间变化。参考 ACN 的 Maintainer 在采纳前重新检索并比较包含候选集合的语义指纹，两条自然争议都经过三轮提案与验证，最终因第三次候选变化停止自动处理、等待人工，没有 Resolution 或后续裁决投递。这属于参考 Router / Maintainer 的联动限制，本轮未修改其代码；不能把早期固定样本的成功概括为真实开发中自动仲裁已经稳定。具体复现与源码关系见 [EatWhich 团队开发验收](validation/2026-10-26-eatwhich-team-development.md)。

同日按用户要求，以 `rerank_enabled=false`、无 embedding 的 Router 复验，DSH 与 Maintainer 继续使用 `deepseek-v4-flash-api`。两个 scope 共 20 次重复查询的结果分别稳定，Router 模型调用为 0；两条原争议均首轮自动采纳、输入变化计数为 0，随后经 Inbox 送达三个成员，界面 Claim 的无条件“预览只读”被原地收窄并回传团队。因此当前这条真实开发链路在词法 Router 配置下已通过；开启模型重排的限制仍然存在，按用户要求暂不修改自裁决实现。复验使用首次收尾后的 30 条 Claim 副本，不能冒充同一份 29 条快照的严格配对实验。

`consult_router` 返回 Claim 关联的已解决争议 ID 和 dispute 的 resolved 状态，但不返回完整 Resolution 或仲裁内部阶段。属性建议若没有引起 Claim 正文改写，裁决 ID 也未必出现在知识证据中；当前需从 Maintainer 管理接口或持久记录查看完整裁决。关闭重排后的新会话实测正确说明了这一信息边界，没有把未提供的 ID 或阶段补写成事实。

[2026-10-26 EatWhich 团队开发](validation/2026-10-26-eatwhich-team-development.md)验证了真实业务开发、跨成员发现和 Policy 内化，也暴露出共同错误假设可以随知识传播：首轮代码与测试共同接受了“排队即保存成功”，由独立审查发现后才修正。另有两个成员将 update 的 `expected_revision` 误写成 `revision`；严格校验拒绝，但当前通用错误反馈未指出具体字段，本次需要执行者提供 schema 提示。不能将这些过程描述为完全自主的可靠协作。

同轮还观察到：一个需负责人决定的相同快照恢复边界，在形成和复用时逐渐被表述成强制要求与已知漏洞。可复现的代码现象不能自动证明产品必须采用某种规则；confidence、引用和证据摘要仍需要保留这一层区别。

[2026-10-25 实际使用审核](validation/2026-10-25-usage-audit.md)观察到：跨项目复用能保留主要重试规则，但不能自动补全原规格的版本门控和返回值契约；一次回答误称 v1，一条形成结果把本次临时操作要求泛化成流程规则。Claim 的结构合法、可引用和可恢复不等于经验完整、适用范围判断正确。本轮是明确要求查阅知识的少量案例，不是无提示召回率或知识正确率基准。

Dream 有固定候选上下文预算，按更新时间排序截取，报告包含 omitted 数量；没有保证多次运行一定遍历到所有旧知识。Router 首轮使用词法检索与真实模型重排，后续复验关闭重排，两轮均未配置 embedding。重排故障可退回词法结果，但当前插件工具不返回 `retrieval_debug`，模型不能仅凭工具正文确认发生过降级；需查看服务诊断。

## Memory 的保护范围

自动 review 需要有界窗口内同时保留用户与助手条目。EatWhich 长编码回合的实际窗口达到 `maxTranscriptChars=32000` 后，用户条目被工具轨迹挤出；即使达到 `intervalTurns`，也可能没有 review 任务。该条件不影响显式 Memory 工具和冻结快照，但“每 N 轮”并非无条件保证，详见上述实测记录。

M7 已完成私有双文件、工具、扫描、快照和 review。基线没有 fs 读取前事件，因此路径保护位于已知工具最终门禁，另监听写入/编辑意图。它不限制任意 shell、Node 直接 I/O 或自定义工具，也不提供跨 provider/OS 对抗性路径竞争的沙箱保证。当前实测 provider 是同机 fs-local；未声称验证远端共享挂载的隔离。

私有正文不被自动知识/团队流程读取，程序桥 Memory 调用及外层代码/回显被过滤；普通助手若主动复述私有事实，后续对话投影可能看到这些文字。安全扫描与 prompt 约束不能证明语义上绝不泄漏。review 会将自身私有快照发给已配置的模型供应端；“私有”指 Agent 数据与团队知识隔离，不表示模型离线运行。
