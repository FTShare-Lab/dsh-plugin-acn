AGENT CLAIM NETWORK · 0.1.0

ACN记忆框架
使用说明

ACN记忆框架为 DSH 保存可复用的知识与个人记忆。照常开展工作，在需要时查阅经验；接入团队后，也能发现其他成员分享的结论。

DSH 仍负责对话、执行任务和读写项目文件。ACN 在此基础上管理知识与记忆，不替换你的日常开发工具。

  1. 01正常工作完成开发、排查或研究，留下验证过程。
  2. 02复盘沉淀提炼值得保留的结论，记录范围和依据。
  3. 03查询复用在后续工作中查阅，判断是否适用。
  4. 04团队流动按需共享结论，接收并处理团队建议。

可以先单人使用。不需要部署团队服务，也不需要手工修改 YAML。多人协作时，再配置 Router 和 Maintainer。

适用插件：0.1.0 · DSH 声明支持：≥ 0.2.1-rc.2，< 0.3.0。截图来自 macOS 隔离示例环境，名称、知识与模型仅作演示。Windows 已配置兼容性测试与 CI，尚未完成桌面实机验收。

1　安装与首次配置

安装插件

DSH 左侧「插件」→「添加插件」下拉菜单 →「安装第三方插件」

  1. 准备可信的 dsh-plugin-acn-0.1.0.tgz 安装包。当前版本尚未公开发布，请向提供者取得安装包；已有安装包时无需安装开发工具。
  2. 填写安装包在 DSH 所在电脑上的完整路径，点击「安装」。若浏览器与 DSH 不在同一台电脑，文件应放在运行 DSH 的电脑上。
  3. 点击「立即启用」，再打开「ACN记忆框架」。已安装时直接进入下一步。
需要自己从源码打包？

在插件仓库目录，使用 Node ^22.19.0 || >=24.0.0 与 pnpm 11.25.0 执行：

pnpm install --frozen-lockfile
pnpm pack --pack-destination .artifacts

生成的安装包位于 .artifacts 目录，再按上面的网页步骤安装。

创建一份工作配置

设置 → ACN 插件设置 → 工作配置 → 新建工作配置

一份工作配置就是一套独立的知识身份：包含 Agent ID、知识和私有记忆，可单人使用，也可连接团队。

  1. 填写 Agent ID，例如 coding。单人使用可自取固定名称；团队成员使用管理员确认的 ID。只用小写字母、数字、下划线或连字符。
  2. 可填写显示名称，例如“开发”。先保持「连接团队服务」关闭，点击「保存配置」。首份配置会成为默认配置。
  3. 切到「知识与模型」，选择可用的知识处理模型，等待检查通过并自动保存。没有可选模型时，先在 DSH「设置 → 模型」完成配置。
两个模型分别设置。

输入框旁的模型负责聊天和开发；「知识处理模型」负责复盘、团队收件、Dream 和记忆复核。也可以选同一个模型。「沿用会话模型」需要这份配置已有可用的会话模型记录。

知识目录通常保留默认值即可。需要将记忆分开，例如“开发”和“审查”各用一套知识，就创建两份工作配置。同一配置下的不同项目共用知识与记忆，不同配置相互隔离。

2　开始工作会话

选择项目 → 新建会话 → 输入框下方「ACN」

  1. 在新建的空白会话中打开 ACN 菜单，确认当前工作配置。首条消息前可以改选。
  2. 选择聊天模型，正常提出开发或研究任务。单人模式不需要等待团队连接。
  3. 首次发送后，工作配置固定。需要切换知识身份或团队时，请新建会话。

不用每次重选。新会话优先沿用同项目最近新建会话的有效配置，没有可用记录时采用全局默认。在配置编辑页开启「设为默认」并保存，可修改全局默认；它不会改绑已有会话。

安装前的旧会话仍能正常使用。

旧会话，以及未选择配置就已开始聊天的会话，显示 ACN「未启用」：可以继续聊天和操作项目，但不能中途加入 ACN。要使用知识与记忆，请另建空白会话，原聊天记录不会自动导入复盘。

3　复盘与查看知识

完成工作后，整理一次经验

让 Agent 照常完成实际任务。完成一个阶段后，打开 ACN → 复盘本次会话，或输入 /recap。复盘在后台进行，可以继续聊天。

打开 ACN → 知识与活动 → 处理活动，查看是否完成；再切到「本地知识」，阅读形成的结论。

名称你会看到什么
Claim · 知识一条可复用的判断，包含正文、适用范围、置信度和证据摘要。
Trace · 来源知识处理的来源与产物记录，可帮助追溯对应会话和相关知识。
Dispute · 争议相互冲突的知识及其依据。团队模式可上报给 Maintainer 处理。

新建同一配置的会话，继续做相关工作，Agent 可以按需查询和使用这些经验。例如：

继续完善接口的读取重试策略。先参考已有的相关经验，结合这次接口是否幂等、当前版本和测试结果，给出最小修改方案。

一次复盘不保证新增知识。没有新内容，或只有临时进度时，可能不创建任务或产出为 0。成功表示流程完成，重要结论仍需核对当前代码和证据。

什么时候会自动复盘？

时机条件
批量空闲尚未处理的内容达到 10 个已完成人工交互轮次，或约 10 万估算 token，再连续空闲至少 5 分钟。
尾部空闲有尚未处理的新内容，连续空闲至少 1 小时，不要求达到 10 轮。
上下文压缩DSH 成功压缩上下文后，安排相应范围的复盘。是否启用压缩由 DSH 配置决定。
归档会话对剩余内容进行收尾（Finalize），随后暂停自动复盘。撤销归档并真正续聊后才恢复；仅查看不恢复。

单人和团队模式都支持。需要 DSH 运行、模型可用且会话前台空闲；达到条件后先排队，通常每 30 秒检查一次。估算 token 用于触发判断，不是模型账单用量。

看懂处理结果

  • 本地处理完成：本轮结果已应用到本地，不等于团队已收到。
  • 已同步：当前这份知识已获当前团队的投递回执，不等于其他成员已经采用。
  • 待投递：本地已有结果，团队投递尚未完成；展开活动查看原因。
  • 本地：没有当前版本的团队投递回执；Trace 本来就不上传团队。

浏览和刷新知识页只读取本地数据，不同步收件，也不调用模型。遇到失败，先看活动详情的具体原因，再使用页面提供的「重试任务」「继续任务」或团队投递恢复操作。

4　接入团队 · 可选

团队成员各自在 DSH 工作，共用 Router 和 Maintainer。插件连接这些服务，帮助知识流动，不自动分派多 Agent 编码任务。

Agent · 你的 DSH

执行任务，维护本地知识，判断是否采用团队提供的结论。

Router · 查询服务

按主题和范围查找团队知识，返回候选记录与来源。

Maintainer · 团队维护

接收共享结论、处理争议，并向相关成员发送建议。

填写团队连接

ACN 插件设置 → 工作配置 → 配置 → 连接团队服务

向管理员取得两个服务地址，以及与你的 Agent ID 匹配的团队鉴权密钥。没有服务时，可参考 ACN 原仓库部署 Router 和 Maintainer。

填写项说明
Agent ID沿用当前配置的身份，并与管理员确认的成员 ID 一致；入队无需再配置第二个身份。
Router 地址管理员提供的查询服务根地址，含 http:// 或 https://。
Maintainer 地址管理员提供的维护服务根地址，保留部署路径前缀，通常不要加管理台的 /app。
团队鉴权密钥直接粘贴团队 key；无需鉴权时留空。默认隐藏明文，眼睛按钮可切换本次输入的显隐。
  1. 开启「连接团队服务」，填写信息。
  2. 点击「检查连接」，分别核对两个服务的检查结果；检查本身不会保存。
  3. 点击「保存配置」。密钥由 DSH 托管，重新打开时不回显；留空保留已有密钥，移除绑定需明确点击对应操作并保存。
  4. 新建会话并选择这份配置，开始团队工作。首发准备会同步收件；同步失败时按提示重试，也可继续使用本地知识。

原单人配置接入团队后，原知识仍能本地使用，不会把单人时期的历史知识整库补传。要区分不同团队，建议新建工作配置；直接修改地址会沿用知识与待投队列，符合重试条件的记录可能送往新地址。

查询、共享与同步

  1. 共享经验：成员完成工作并复盘，有共享产物时进入投递队列；在活动和同步标签中确认结果。
  2. 发现经验：其他成员提出相关任务时，Agent 可通过 Router 查询候选知识，结合当前范围判断是否采用。不会把团队全部知识复制到每个成员本地。
  3. 接收建议：打开 ACN → 同步收件，或输入 /inbox。处理活动显示收件与内化结果；“内化”是模型结合本地知识处理建议，可能修改知识，也可能保持现状。

例如：成员 A 验证某接口只允许幂等读取重试，复盘保留适用范围与测试依据。成员 B 开发相关逻辑时，可以查到这条经验，核对当前接口与版本后再采用；若发现相反证据，则保留依据、形成争议，交给团队处理。

需要立即接收管理员刚发布的规则或裁决时，请手动同步。知识页的「刷新」不能代替「同步收件」。新知识目录通常在后续模型步骤提供；私有 Memory 快照仍固定到会话，修改后需新建会话读取。

争议处理完成，不等于所有人已经收到或采用。

自动仲裁需管理员在 Maintainer 启用并配置模型。正式采纳后，通知发给直接涉争 Claim 的持有者，经收件、内化、重新投递才可能形成更新；其他成员通过 Router 查询后续版本。收件确认（ACK）只表示已收妥。

修改、停用配置与管理台
  • 停用配置并保存会暂停关联会话，数据保留；重新启用原配置可恢复。不要通过修改 Agent ID 给旧会话换身份。
  • 修改 Agent ID 或知识目录不会迁移旧数据，可能使旧会话无法访问原知识。需要新身份时优先新建配置。
  • 修改服务地址或密钥供新启动实例采用，已驻留实例可能保留旧连接；旧会话冷恢复后使用该配置当前保存的团队地址。不同团队需用不同配置隔离。
  • 管理台供团队管理员使用，团队成员 key 不能代替管理员登录。普通成员无需进入管理台完成收件或知识内化。
管理员：Router 的模型配置

当前推荐 Router 使用不带 LLM 重排的检索。重排可能改变候选集合，触发 Maintainer 的输入变化保护，使自动仲裁无法采纳。此建议不影响 DSH 或 Maintainer 分别使用模型。

5　私有记忆与知识整理

Memory：保存长期有用的个人经验

例如告诉 Agent：

请记住我的沟通偏好：说明测试结果时，区分已验证的结论与尚未验证的范围。

插件用 MEMORY.md 保存稳定经验，用 USER.md 保存稳定用户事实与偏好，也会定期复核。不要把一次性进度、日志或凭据当成长期记忆。

私有双文件不直接上传团队；记忆复核仍将必要输入交给所选模型服务处理。“私有”指与团队知识隔离，并不表示离线运行。新会话读取新快照，现有会话继续使用原快照。

Dream：整理已经积累的知识

  1. 在已启用 ACN 的会话输入 /dream，开始整理。
  2. 到「知识与活动 → 处理活动」查看阶段、已用请求次数、更新和未完成项。
  3. 需要暂停时输入 /dream stop，之后可继续；报告生成后可在活动详情复制路径，在运行 DSH 的电脑上打开。

有足够的知识变化并满足冷却时间后，插件也会定期检查并自动整理，手动运行无需等待这些门槛。Dream 会清理一次性记录、整合相关知识并保留历史，要求保留有效条件、版本、例外和证据限制；没有安全的改进时可以不改。整理后仍应检查重要规则的适用范围。

费用与查证范围

默认每次最多 24 次探索请求，再额外最多 3 次收尾请求；失败重试也计次。额度用完后本次收尾结束，未完成项会明确记录；再次发起整理会读取当前知识开始新任务。后台单次输出上限默认 32768 token。

工作区文件查证默认关闭，需在高级配置中启用；启用后只提供受限的只读查证，不提供任意命令或联网搜索，不读取私有双文件。普通使用无需修改这些参数。

6　遇到问题，先看这里

优先打开 ACN → 知识与活动 → 处理活动，展开失败项。先修正原因，再使用该记录上的恢复操作；浏览列表不会重新调用模型。

聊了很多，却没有新知识

确认会话已绑定工作配置，再看是否有复盘任务。未达到空闲门槛时可手动「复盘本次会话」。任务完成且产出为 0，表示本轮没有需要新增或修改的知识，不一定是故障。

聊天正常，但复盘、收件或 Dream 失败

先看错误分类。网络、鉴权、额度或模型响应问题，检查「知识与模型」及模型服务，再重试任务。工具参数格式错误会有限自动恢复；仍失败时可重试或换知识处理模型，合法参数仍需通过校验。

若提示本地文件不可写、锁超时或输入未准备完整，检查 DSH 所在电脑的文件占用、磁盘与目录权限，再重试复盘。保留原会话日志，重启可补回尚未处理的记录；正文损坏、内容冲突或容量超限请联系维护者，更换模型无法修复本地数据。

团队同步失败，或者两个服务检查结果不同

到对应工作配置点击「检查连接」。地址或超时错误需核对地址、网络和服务状态；鉴权错误需核对 Agent ID 与团队密钥，并确认两个地址属于同一套团队服务。修改后保存，回原会话「重试同步」，再看处理活动。

健康检查通过不保证所有业务请求成功；本地处理完成也不保证投递完成。保存时若提示有 Agent 正在运行，等待当前轮结束；若旧实例仍使用旧连接，重启前确认会话空闲。

管理员处理了争议，我没有看到变化

请管理员确认已正式采纳并通知对应 Claim 持有者。接收成员同步收件后，核对收到数量、内化结果和 Claim 内容。通知不向全员广播，内化也不保证必须改动；其他成员可查询团队最新知识。

旧会话显示「未启用」，或者身份不匹配

没有绑定记录的旧会话仍可普通聊天，但不能中途加入 ACN，请另建空白会话。已绑定会话若因配置停用或 Agent ID 改动失效，请恢复原配置；不要给旧会话改绑另一身份。

保存冲突，或者不确定是否保存成功

点击「刷新并保留草稿」，核对已保存值后再决定是否重试。团队连接冲突需选择保留一整份连接；不要混用两个窗口的地址、身份与密钥。「重新加载已保存配置」会丢弃未保存修改，取消编辑也会放弃当前草稿。

暂停、归档或记忆更新后，为什么没立即生效？

暂停任务用「继续任务」，失败任务用「重试任务」；继续后可切到「查看全部活动」跟踪。撤销归档后需真正续聊才恢复自动复盘。私有 Memory 更新则需新建会话读取新快照。

怎样备份、迁移和反馈问题？

在「知识与模型」确认知识根目录，升级或迁移前先备份整个目录。修改目录不会自动搬迁旧数据；不要让插件与独立 ACN 同时写同一份活动数据。已有 ACN 数据可通过导入命令先做只读预览，完整操作见仓库命令参考。

反馈时提供插件与 DSH 版本、活动 ID、失败时间和错误截图。不要提供团队 key、模型密钥或私有 Memory 正文。

命令与参考

大多数日常操作可从 ACN 菜单完成。偏好命令行时，可在聊天框输入：

命令用途
/acn-status查看当前身份、连接、数量与任务状态。
/recap复盘尚未处理的会话内容。
/claim查看知识列表；也可用 /claim show <id> 查看详情。
/inbox团队同步与本地内化；单人模式不请求团队。
/dream
/dream stop		开始或继续整理，或请求暂停。
/acn-finalize主动收尾当前新增内容；不会替你归档会话。

完整参数、迁移与恢复规则见插件仓库的 docs/config.md 与 docs/command-reference.md。本说明介绍 DSH 插件；团队服务与管理员操作以实际部署版本为准。
