# 2026-10-25 实际使用审核与恢复验收

本次在五个隔离 DSH 实例、虚构项目和本机 ACN 服务中验证实际使用。结果支持 ACN 用于可引用经验积累、私有偏好记忆和团队知识传播；也确认了知识摘要不能替代完整规格，模型质量仍需复核。未提交 Git、未推送、未发布。

## 范围与环境

- 插件基线：`feature/web-configuration`，`42a4cf7` 加本次工作区变更；保留此前配置页、名称和文案修改。
- 宿主 DSH `0.2.1-rc.2`，本机 Node `26.4.0`、pnpm `11.25.0`；参考服务 ACN `0.3.3`。
- 三个团队身份 `agent-a`、`agent-b`、`agent-c` 使用各自独立 DSH_HOME、知识根和项目，连接同一 Router / Maintainer；另有单人开发实例与启用证据校准的单人实例。
- 对话、Recap、Finalize、Inbox、Dream、Memory review、Router 重排及 Maintainer 提案/独立验证统一请求 `deepseek-v4-flash-api`。真实模型代理只转发请求、记录无正文的阶段元数据，并提供等待门闩和可控 503；没有伪造模型成功结果。
- Router 启用词法检索与模型重排，未配置 embedding；Maintainer 启用自动仲裁，置信阈值 0.90。团队鉴权启用，凭据仅在测试进程环境与内存中传递。
- 初始开发知识为空。团队冲突、Dream 重复项及证据错误使用另行注明的合成夹具，不能算作模型自主发现的真实事实。
- 真实操作经过 DSH 会话、命令、模型工具、安装包及持久存储；网页配置使用实际浏览器检查。主循环、文件工具、压缩和会话运行均由 DSH 提供。

## 虚构开发与知识复用

项目 Queue Ledger v2 实现纯函数重试判定：仅幂等 READ、正且有限预算、非负整数尝试次数且小于 2 才允许重试；WRITE、非法输入和耗尽预算拒绝。原项目另明确 v3 未验证并测试版本排除。

| 场景 | 实际观察 |
| --- | --- |
| 团队 A 从空知识开发 | 读取 SPEC，编写实现与测试，28 项通过；Finalize 形成 medium Claim `claim_669f5a63` 与 Trace |
| 单人从空知识开发 | 完成同一规格，26 项通过；形成两条重试边界 Claim |
| 团队 B 在空白 consumer 项目复用 | 不复制 SPEC；实际 consult_router 得到 A 的正文，引用来源实现，17 项测试通过；Finalize 保留上游引用 |
| 单人新项目复用 | 新会话实际 claim/read 读取两条已有知识，形成独立实现，16 项测试通过 |
| 独立行为检查 | 四个实现各通过 12 个核心重试用例；原实现拒绝显式 v3，两个复用实现缺少该门控 |
| Recap 正常形成 | B 第二次 `/compact` 压缩 9 条历史、约 3656 tokens，Recap `96451c43-5f7f-4ce9-9586-32f36aca7d00` applied |
| Recap 去重边界 | 一次被随后 Finalize 标为 superseded；A 压缩已处理区间时返回 already_processed，没有重复形成 |

复用确实降低了重新说明核心规则的需要，但本轮明确要求先查阅知识，没有测无提示自动召回率。B 识别并注明 Claim 缺少部分 reason token 与版本门控；单人复用的回答却出现“v1”的错误称呼。另有冲突分析 Claim 把本轮“不要手工编辑”的临时要求泛化为流程规则。这些是实际观察到的语义质量限制，不能用测试通过或 Claim schema 合法掩盖。

## 三成员团队闭环

1. 以合成夹具放入同一 scope 的两个冲突判断：A 的 `claim_cafe0101` 认为 120 秒等于 2 分钟；C 的 `claim_cafe0102` 故意写成 3 分钟。两者都限定 v2，声明 v3 和运行时未验证。
2. C 在真实 DSH 中读取本地 Claim 和 Router 返回的 A 正文，比较后通过 Finalize 形成 `dispute_714e0a09`。没有通过测试脚本替模型填写 Dispute。
3. Maintainer 实际调用提案和独立验证模型。首轮分析期间 Router 候选发生变化，按服务规则等待约五分钟重分析；随后自动采纳 `resolution_2fc415af`，状态 resolved，保留正确项并建议废弃错误项。
4. A、C 各收到一条消息；C Inbox 内化后将自己的错误 Claim 改为 deprecated/low，保留 `policy_1ca5f953` 来源。B 未作为直接当事人收到该消息，但之后查询能得到有效的 2 分钟结论与 resolved dispute ID。
5. 发布租户缓存键 Policy `policy_3b7f28ff` 给 A/B/C，三个 Inbox 各形成一条本地引用知识；撤回后，三个直接依赖 Claim 均废弃并同步。

Router 实际执行模型语义重排。故意返回模型 503 时，服务仍给出词法候选并记录 `rerank_fallback=true`；恢复后重新使用模型。DSH 中 C 也实际发出包含 `semantic_query` 的查询并收到可用候选。插件当前不向工具暴露 `retrieval_debug`，模型如实表示无法从返回值确认降级；纯 scope 查询不要求语义重排，不能拿它证明重排成功。

Maintainer 被 SIGKILL 后，A 的真实 `/claim set` 仍完成本地持久化并显示待同步。服务重启后调用 `/inbox`，实际补传 1 条 Claim，队列排空；没有借机更改日常配置或生产团队。

## 审核发现、修复与回归

| 缺陷 | 修复与证据 |
| --- | --- |
| P1：形成/内化的分析快照被并发修改后，旧结果被丢弃却消耗输入 | 首次 prepared 前在知识锁中检查，抛可重试 AnalysisChanged，保留 transcript/Inbox；新增真实 I/O 回归。真实 DSH Finalize `82698df2-6f81-42f0-b445-9d83f944dd87` 在模型等待时并发修改 Claim，attempts=2 后 applied |
| P1：停止 DSH 后改身份/目录可让旧日志进入新身份 | 宿主会话持久身份摘要绑定，重建对象与 fork 继承验证；无身份历史要求新会话，未配置时不阻断宿主。包含新建子会话父身份校验，避免错误阻断合法 spawn |
| P1：旧团队队列与单人期间修订不一致时仍能发布；自动刷新还会漏掉后续整合依赖 | 移除上传阶段自动替换正文；每个版本先核对本地，一致才继续，保留待传项与依赖 Dispute。覆盖普通修订、单人 A→B，以及既有团队 A→B 后单人 B→C；显式受审查重绑后才先交付承接者；编辑日志恢复只接受精确 target，防止遗留日志把单人第三版本重新入队 |

独立审查使用配置默认的 `gpt-6-astra` 和 CLI `0.164.0-alpha.11.1`，直接只读执行，禁止嵌套审查、子代理、写文件和运行测试。初审及后续复审均用于发现真实 P1，未将任何有发现的审查计为通过；上传复审进一步发现遗留编辑日志能重新入队单人第三版本，已改为仅接受精确 target 并补回归；最后一次恢复逻辑增量审查未发现剩余 P0/P1。各模块最终结论合并使用，不把末轮窄范围审查描述成重新扫描了整个仓库。

## 崩溃、导入与身份切换

- Finalize `398c8f14-f355-4fc1-9012-d27625d02b97` 在真实模型请求等待中被 SIGKILL；重新安装当前包并启动同一隔离 DSH_HOME 后，原 ID 从 running/attempts=1 接管为 attempts=2，最终 applied。恢复原会话可读取原 Claim。
- 实际 `/acn-import` 对带空格的合成源路径预览时不写入；导入 1 条 Claim 后字节完全相同，重复导入跳过 1 条，源不变；混入其他 holder 后拒绝且没有发布越权条目。该单人操作没有形成上传队列。
- 停止隔离宿主，保持 sessionEpoch=0，修改身份后重启；旧会话命令明确拒绝，旧会话尝试读取新身份私有标记时在模型前被拒绝（新增模型调用 0 次），没有泄露标记；新会话使用新身份并读到空 Claim 列表。

## 自动化范围和解释边界

最终验证：strict 类型、ESLint、安全扫描、28 份 Markdown 文档链接检查通过；58 个测试文件共 **774 项**常规测试通过；**47 份**协议夹具经 TypeScript/Rust 回读通过；真实 Router/Maintainer **6 项**契约测试通过；构建、类型声明、打包及临时 DSH_HOME 的 CLI 安装验收通过，含不兼容引擎拒绝。虚拟开发额外完成 28/26/17/16 项项目测试和四组各 12 项独立行为检查。测试服务在结束后关闭，证据保存在本次本机临时验收目录。

自动化重点还覆盖本次现场未逐一制造的边界：401/403、取消/超时、伪造引用、过期 revision、符号/硬链接、路径越界、证据预算与文件版本变化、子代理写权限、Memory 双文件事务和多个 prepared 强杀点。现场 SIGKILL 发生在模型阶段，不能替代这些提交阶段的自动化恢复测试。

本次没有进行生产规模、多机/远程文件系统、网络分区压力测试，也没有系统性评价知识事实正确率、无提示召回率或长期收益。自动仲裁的受控单位换算案例证明管线联通，不能证明复杂业务争议都能可靠自裁决。建议将 Claim 用作带来源和范围的经验材料，关键版本约束与接口契约仍对照项目规格和测试验证。
