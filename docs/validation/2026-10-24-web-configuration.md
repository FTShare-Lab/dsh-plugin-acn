## 实际网页安装与使用

所有 ACN 字段均在网页填写，未手动编辑验收 profile 的 ACN YAML。

1. 从空 profile 打开“插件 → 添加插件下拉菜单 → 安装第三方插件”，输入本地 tarball 路径，安装并立即启用。九个组件运行正常，插件详情显示配置表单。
2. 填写 `agent-a`、独立临时知识目录，选择 `deepseek-v4-flash-api` 和单人模式。保存显示成功及实际 `agents/agent-a/` 路径。非法 `../invalid` 身份被拒绝；重新加载仍为原值。
3. 真实模型读取虚拟工作区 `contract.txt`，总结幂等读、显式重试预算和写操作边界。执行 Finalize 成功，产生 1 条 Claim 和 1 条 Trace；后台审计确认使用指定模型。
4. 停止并重启同一隔离 DSH，页面保留 Agent ID、知识目录、模型及启用状态，知识文件保留。验收脚本现在只初始化不存在的 profile，重启不会用默认 profile 覆盖网页保存结果。
5. 启动真实 ACN Router/Maintainer，在配置页填入两项回环地址、测试身份的凭据变量名及 180000 毫秒超时。`/acn-status` 显示 Router=ok、Maintainer=ok；`/inbox` 成功拉取与处理空队列，持久任务 succeeded。
6. 真实会话使用 `consult_router` 返回 `available: true`，并通过 `claim` 读取原有知识。修改测试 Claim 的置信度后，待上传从 1 清零，真实团队服务落盘该 Claim。
7. 网页切换为 `agent-b` 及对应凭据变量名；旧会话 `/inbox` 明确提示身份或目录已改变。新建会话后，指定模型通过 Router overview/query 发现 `agent-a` 的 `claim_f4b67d86`，正确返回 holder、medium 置信度和证据限制。
8. 第二身份执行 Finalize，任务 `20960fe6-37cb-4b6f-a7fb-c0c53d5595cf` succeeded、attempts=1，写入 Trace；后台调用审计为 `deepseek-v4-flash-api`、succeeded。

上述验证的是网页配置驱动的安装、持久化、真实模型及团队通信链路。本次团队辅助服务关闭了模型语义重排与自动仲裁，没有重复上一轮三成员冲突仲裁/Dream 质量验收；此前覆盖见 [2026-10-23 团队闭环](2026-10-23-model-team-loop.md)。自动化全量仍包含这些功能的既有回归。当前轮没有重新执行 Node 22/24 矩阵或远端 CI。

## 审查修复

首轮独立只读审查发现一项 P1：配置热重载后，存活旧会话可以通过新注册工具访问新身份的数据，冻结 Memory 缓存也会丢失。已增加运行中保存门禁、应用期间的进入门禁、持久身份切换时间边界、工具/命令/事件校验，以及同一存储重载的冻结快照恢复。上述真实 Agent 测试和网页双身份测试验证了修复。复审指出宿主会在版本检查前重载外部磁盘配置；进一步使用不可变会话 Header 的首次存储绑定阻止预重载阶段改绑，保留外部配置并持久更新会话时间边界，防止恢复旧会话绕过。新增真实 profile 竞争回归覆盖这一路径。进一步在预重载后插入另一页面的对话输入，确认 Agent 已标为 running 时仍先持久化身份冲突边界，随后恢复出的新 Header 也不能绕过。

本机旧独立 CLI 对配置的默认模型返回 400；改用桌面随附新版 CLI，保持其配置的默认模型，完成可用的只读审查。审查全程只读，不执行发布。

最终独立复核确认上述 P1 已解决，限定修复范围内未发现剩余 P0/P1。审查使用桌面随附 CLI `0.163.0-alpha.11.2` 与其配置的默认模型；测试由主执行流程完成，审查进程未修改文件。
