## 实测发现与修正

真实 Dream 草稿把 operation.reason 当作通用解释，还试图删除指向将废弃输入的既有来源。硬校验拒绝这些草稿，未提交无效改动。M8 补充 JSON schema 字段说明、模板纪律和含具体 ID / 类别的反馈：只有特定 quality/deprecate 能用 reason 简写；其他依据放 change_basis，整合必须继承已有来源，弃用不等于删除历史实体。

新增持久 worker 回归依次重放错误 reason、错误来源删除和修复后的草稿；确认前两次均被拒绝，最终保留对弃用输入的来源，完成一组与收尾提交。约束未放宽。

另观察到模型把推理和 `</think>` 放入普通文本块，尾部 JSON 完整但严格解析失败。宿主适配器现在仅识别明确结束边界后的完整 JSON 对象；不截取任意说明中的片段，不修复残缺输出，正文内标签保持原样，之后仍执行完整 schema、引用和权限校验。12 项边界用例及两项真实宿主流程回归验证有效对象可形成 Claim，伪造来源仍拒绝、无写入，丢弃的推理不进入队列。

## 结论边界

实际模型抽样证明这些具体调用能进入真实宿主与持久化链路，不构成知识事实正确率、整合等价性或跨模型质量保证。受限证据与安全边界的系统测试采用本地模型；不能把模式扫描和工具门禁当成 OS 沙箱。

额外对同一 Dream 复核输入直接调用新模型，得到另一份合法的 repair 响应：它认为存续 evidence_summary 没有明确承接被废弃输入的“无法证明同一版本”限制。这与宿主那次通过的语义判断不同，具体说明了逐字引用覆盖和模型自评的局限；本次不把 succeeded 等同于整合内容已经人工确认。

该额外调用使用 32768 输出上限且没有宿主当轮重试反馈，宿主使用 16384；不作为严格同参数的重复评测。具体遗漏已在 2026-10-23 通过完整原证据摘要留存约束、回归和两次真实模型验收补强，见[补充验收](validation/2026-10-23-dream-review.md)。

本地代码复查及自动化测试已完成。独立只读 CLI 审查按配置默认模型执行，因该模型不被当前登录方式支持而返回 400，没有可用审查结论，未计为通过。远端 CI 和正式发布没有执行；进一步限制见[已知问题](outstanding-issues.md)。
